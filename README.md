# Maa NoGithub AutoUpdate

针对无法正常访问 GitHub 的用户，提供的 **MAA** 与 **MaaEnd** 下载与更新工具集。

- **MAA**（Maa Assistant Arknights，明日方舟游戏助手）是一个开源项目，最新版本放在 GitHub 上。
- **MaaEnd**（明日方舟：终末地助手）同样是基于 MaaFramework 的开源项目，托管在 GitHub。

但 GitHub 在国内访问很慢甚至打不开，本项目就是为了解决"下不了、更新不了"的问题。

## 两种更新方式对比

|              | 全量下载覆盖                     | 增量更新（推荐）                |
| ------------ | -------------------------------- | ------------------------------- |
| **适合场景** | 第一次下载 MAA、MAA 损坏需要重装 | 已安装 MAA，日常版本更新        |
| **下载大小** | 完整包（约 250MB）               | 增量包（约 5~50MB），完整包兜底 |
| **下载速度** | 较慢（文件大）                   | 快（差异文件小）                |
| **保留配置** | 保留 config/、data/、resource/   | 自动备份恢复，不丢配置          |

### 全量下载覆盖

**优点**：

- 最简单，不需要任何前置操作
- 双击 bat 自动下载、自动覆盖安装
- 适合新手和完全不懂的用户
- 脚本会自动保留 config/data/resource 配置

**缺点**：

- 每次下载完整包（~250MB），比增量包大很多
- 网络差时下载时间较长
- 无法进行资源更新，建议配合增量更新脚本

### 增量更新（推荐）

**优点**：

- 下载量小（差异文件通常几 MB 到几十 MB）
- 支持只更新版本、不更新资源
- 可以配合 MAA 实现全自动更新（启动前脚本）
- 支持断点续传
- OTA 增量更新效率最高

**缺点**：

- OTA 找不到差异包时会回退到完整包

## 小白使用攻略

### 第一步：下载 MAA（从未安装过）

1. 下载本项目：百度网盘链接在最上方，或从 GitHub 下载
2. 解压后进入 `Maa_增量全量更新脚本\` 文件夹
3. 双击 `Maa-全量更新-静默.bat`（静默模式，无弹窗干扰）
4. 等待下载完成（约 250MB，根据网速 1~10 分钟）
5. 下载完成后脚本会自动覆盖安装到当前目录
6. 如果当前目录不是 MAA 目录，手动把下载的 zip 解压到 MAA 目录即可

### 第二步：日常更新（已安装 MAA）

1. 进入 `Maa_增量全量更新脚本\` 文件夹
2. 把里面所有文件**复制**到 MAA 安装目录（与 MAA.exe 同目录）
3. 双击 `Maa-增量-静默版本资源全部更新.bat`（版本+资源全更新）
4. 或者双击 `Maa-增量-静默只更新版本.bat`（只更新版本，跳过资源）
5. 如果想查看更新过程，双击 `Maa-增量-更新-Debug.bat`（保留窗口）

### 第三步：设置自动更新（可选）

1. 打开 MAA → 设置 → 运行设置
2. 将 `Maa-增量-静默版本资源全部更新.bat` 拖入"开始前脚本"
3. 之后每次启动 MAA 都会自动检查并更新

## 详细使用说明

### 方式一：全量下载覆盖

适合：第一次下载 MAA、MAA 损坏需要重装、完全不懂的新手

1. 进入 `Maa_增量全量更新脚本\`
2. 双击其中一个 bat：

   | 脚本                     | 说明                   |
   | ------------------------ | ---------------------- |
   | `Maa-全量更新-静默.bat`  | 静默下载覆盖，无弹窗   |
   | `Maa-全量更新-Debug.bat` | 保留窗口，便于查看输出 |

3. 脚本自动执行以下流程：
   - 获取最新版本信息（从 api.maa.plus）
   - 测试各镜像源速度，选择最快源
   - 下载完整安装包（约 250MB）
   - 检测当前目录是否为 MAA 安装目录
   - 如果是：备份 config/data/resource → 清理旧文件 → 解压覆盖 → 恢复配置
   - 如果不是：仅下载 zip，需手动解压
   - 删除已下载的安装包

### 方式二：增量更新

适合：已安装 MAA 的日常更新、希望自动更新的用户

#### 首次使用

1. 进入 `Maa_增量全量更新脚本\`
2. 把里面所有文件**复制**到 MAA 安装目录（与 MAA.exe 同目录）
3. 双击 `Maa-增量-更新-Debug.bat`（保留窗口，便于查看输出）
4. 脚本会自动：检测版本 → 下载增量/完整包 → 备份 → 安装 → 重启 MAA

#### 日常使用

| 脚本                                      | 说明                                     |
| ----------------------------------------- | ---------------------------------------- |
| `Maa-增量-静默版本资源全部更新.bat`       | 版本+资源全更新（正式版，推荐）          |
| `Maa-增量-静默只更新版本.bat`             | 只更新版本，跳过资源更新（正式版）       |
| `Maa-增量-更新-Debug.bat`                 | 保留窗口，适合首次运行/查看输出/反馈问题 |
| `Maa-增量-静默版本资源全部更新(beta).bat` | 版本+资源全更新（公测版）                |
| `Maa-增量-静默只更新版本(beta).bat`       | 只更新版本，跳过资源更新（公测版）       |
| `Maa-增量-更新-Debug(beta).bat`           | 保留窗口调试（公测版）                   |

游戏资源更新不稳定，建议在 MAA 内更新资源。

#### 更新逻辑

- **版本比较**：语义化版本比较（SemVer），支持 `6.19.2`、`6.19.2-beta.2`、`6.19.1-alpha.1.d096.gf94342d3e2` 等写法，
  正式版恒大于同号公测版（`6.19.2 > 6.19.2-beta.2`）
- **beta 通道按时间取最新**：用 beta 脚本时会同时比较 **beta 公测版**与 **stable 正式版**，取更高者。
  因此当 6.19.2 已正式发布、beta 通道还停在 6.19.2-beta.2 时，beta 脚本同样会更新到 6.19.2，不会再误报"已是最新"
- **OTA 包按源版本区间匹配**：优先完全同名 OTA → 当前版本"基础版本号"对应的 OTA
  （如当前 `6.19.2-beta.2.d010.g…` 用 `beta.2` 的包）→ 所有源版本 ≤ 当前版本中最贴近的一档；
  官方没有对应增量包时自动回退完整包
- **版本更新**（三级回退）：优先 OTA 增量包（几 MB~几十 MB）→ OTA 失效则完整包 → 都失败时自动调用全量下载脚本覆盖安装
- **资源更新**：jsDelivr CDN 取资源版本 → GitHub 镜像兜底；下载后按时间戳比较，确实有新资源才覆盖本地 `resource`
- **线路自动探测**：下载前实测「直连 GitHub / 代理 / 各镜像」的可用性与速度，按实测结果排序后再下载；
  直连或代理够快时自动跳过镜像探测
- **安装流程**：先下载（MAA 仍在运行）→ 下载完成 → 自动关闭 MAA → 备份 → 安装 → 重启 MAA
- **断点续传**：使用 `.update_state` 文件记录状态，重新运行从断点继续
- **自动回滚**：备份在 `.update_backup` 文件夹，失败自动恢复
- **SHA256 校验**：下载后自动验证文件完整性，防文件损坏；校验失败自动换源重试
- **代理适配**：支持 `http://` 与 `socks5://` 代理（SOCKS5 走 curl）；使用代理时不再做 IP 钉定（`--resolve`），
  避免解析结果与代理出口不一致导致下载失败

## 首次运行说明

- 第一次启动会比较慢，请耐心等待
- 脚本会自动检测并安装 PowerShell 7（用于 HTTP/2 下载）
- 如网络问题无法自动下载 PowerShell 7，按以下顺序尝试：
  1. 从微软商店安装（国内可正常访问）：
     https://apps.microsoft.com/detail/9mz1snwt0n5d?hl=zh-CN&gl=CN
  2. 脚本会自动从微软 CDN 下载安装（dotnetcli.azureedge.net）
  3. 手动下载安装包放到 MAA 文件夹：
     a. 打开 https://github.com/PowerShell/PowerShell/releases
     b. 下载 PowerShell-7.6.2-win-x64.msi 或 .zip
     c. 放到 MAA 程序文件夹，脚本会自动识别安装

- 网络：中国普通宽带/移动网络（已针对国内网络优化）

## 主要特性

- **多镜像冗余**：自动从 `gh-proxy.com`、`ghproxy.net`、`gh.ddlc.top`、`ghproxy.homeboyc.cn` 等多源降级下载
- **线路实测排序**：每次下载前实测直连/代理/镜像哪条能通、哪条最快，按实测结果排序，直连够快时跳过镜像
- **语义化版本比较**：正式版/公测版/夜间版三级版本号都按 SemVer 正确排序，beta 通道自动在 beta 与 stable 间取更新者
- **系统代理适配**：自动识别 HTTP_PROXY/HTTPS_PROXY 环境变量和 IE 代理设置，支持 http 与 socks5
- **多下载引擎**：curl → HttpWebRequest → HTTP/2 → 分片，自动降级
- **增量/全量双保险**：增量更新失败时自动调用 `Maa-FullUpdate-Download.ps1` 全量覆盖
- **自动备份回滚**：备份在 `.update_backup` 文件夹，失败自动恢复
- **无需手动关闭 MAA/MaaEnd**：更新前自动关闭，更新后自动重启
- **不修改系统网络配置**：仅在直连线路使用 curl --resolve 做进程级 DNS 加速，不改 hosts 文件
- **内置自测**：`-SelfTest` 参数可离线校验版本比较与更新包选择逻辑（约 60 条断言）
- **MaaEnd API 降级**：`api.github.com` 不可达时，从网页抓取版本列表继续工作

## 更新通道

默认使用 `stable` 通道。三种方式切换：

1. **使用独立 bat 文件**（推荐）：双击 `(beta)` 后缀的 bat 即可更新到公开测试版
2. **在现有 bat 后加参数**：`Maa-增量-静默版本资源全部更新.bat -Channel beta`

| 参数               | 说明                                       |
| ------------------ | ------------------------------------------ |
| `-Channel beta`    | 公开测试版（同时比较 stable，取更新者）    |
| `-Channel alpha`   | 开发版（同时比较 beta / stable，取更新者） |
| `-Force`           | 强制重装当前最新版                         |
| `-SkipResource`    | 只更新版本，跳过资源更新                   |
| `-SkipVersion`     | 只更新资源，跳过版本更新                   |
| `-DryRun`          | 只检查不下载（确认会不会更新、走哪条线路） |
| `-SelfTest`        | 离线自测纯函数逻辑，不联网不改文件         |

从较旧版本首次切换到 beta 通道时，MAA 官方可能未提供
从该旧版本直达公测版的 OTA 增量包。此时脚本会自动回退下载
最新的正式版完整包。此外，只要 stable 已有更新的正式版，
即使 beta 通道版本号较旧，脚本也会直接更新到该正式版。

## MaaEnd 下载与更新

MaaEnd（明日方舟：终末地助手）仅有全量下载方式，不提供增量 OTA 包。

### 使用方法

1. 将 `MaaEnd_增量全量更新脚本\` 文件夹复制到你想放 MaaEnd 的位置
2. 双击 `MaaEnd-全量更新-静默.bat`
3. 等待下载完成（约 300MB）
4. 脚本自动执行：
   - 从 `api.github.com` 取版本列表；不可达则从 `github.com` 发布页抓取 tag 列表降级
   - `stable` 按发布时间挑正式版，`beta` 在正式版与预发布版间按语义化版本取更高者
   - 实测「直连 GitHub / 代理 / 各镜像」哪条最快，按结果排序下载
   - 检测当前目录是否为 MaaEnd 安装目录（有 `MaaEnd.exe`）
   - 如果是：关闭 MaaEnd → 备份 config/debug → 清理旧文件 → 解压覆盖 → 恢复配置 → 重启 MaaEnd
   - 如果不是：仅下载 zip，需手动解压

### 更新通道

| 脚本                              | 说明                 |
| --------------------------------- | -------------------- |
| `MaaEnd-全量更新-静默.bat`        | 正式版（静默模式）   |
| `MaaEnd-全量更新-Debug.bat`       | 正式版（保留窗口）   |
| `MaaEnd-全量更新-静默(beta).bat`  | 预发布版（静默模式） |
| `MaaEnd-全量更新-Debug(beta).bat` | 预发布版（保留窗口） |

支持在 bat 后追加参数：`-Channel beta`、`-Force`、`-DryRun`、`-SelfTest`。

### 特性

- **自动关闭/重启**：更新前自动关闭 MaaEnd 进程，更新后自动启动
- **API 降级**：`api.github.com` 不可达时，从 `github.com` 发布页抓取 tag 列表继续工作
- **语义化版本比对**：读取本地 `interface.json` 的 `version` 字段，按 SemVer 比较；
  `2.32.0` 与 `v2.32.0` 视为同一版本，不会重复下载；本地版本更高时提示并跳过（不降级）
- **beta 按版本取最新**：beta 通道同时比较正式版与预发布版，预发布版落后时会正确更新到正式版
- **线路实测排序**：下载前实测直连/代理/镜像哪条能通、哪条最快，直连够快时跳过镜像探测
- **代理适配**：支持 `http://` 与 `socks5://` 代理（SOCKS5 走 curl）
- **SHA256 校验**：GitHub 提供 `digest` 时校验，失败自动换源
- **配置保留**：自动保留 `config/`、`debug/` 目录
- **内置自测**：`-SelfTest` 可离线校验版本比较与版本选择逻辑

## 常见问题

**Q: 双击 .bat 闪一下就消失？**
A: 用 Debug 版本查看错误信息。常见原因：文件没放到 MAA.exe 同目录、路径含空格、权限不足。

**Q: 提示 "PowerShell 下载失败" 但后续能更新？**
A: 版本更新走 curl 直连不需要 pwsh，只有资源更新才需要 pwsh HTTP/2。可从微软商店安装或手动下载安装包放到 MAA 目录。

**Q: 下载很慢/超时？**
A: 脚本内置多镜像多策略重试，自动选择最快源。如果总失败，检查代理设置或网络环境。

**Q: 更新后 MAA/MaaEnd 启动异常？**
A: 脚本自动保留备份在 `.update_backup`，手动覆盖回 MAA 目录即可回滚。

**Q: 什么是 OTA 增量更新？**
A: 只下载和旧版本有差异的文件，通常几 MB 到几十 MB，比完整包（几百 MB）快得多。
